# AI超级导演客户提案三层压缩表达协议

## 1. 定位

这套协议用于把完整导演方案压成三层交付：

1. 客户版摘要：让客户一眼判断值不值得买单。
2. 导演版细案：保留创作判断、取舍和现场调度。
3. 执行版提示词：让 Seedance 2.0、剪辑、后期和团队能直接开工。

它不替代项目交付包、类型成片交付标准包和成片级分镜编译器。它只负责压缩表达层级，避免客户被长分镜和技术细节淹没，也避免执行团队只拿到漂亮口号。

## 2. 触发信号

用户出现以下表达时，先调用本协议：

- 给客户看
- 客户提案
- 客户看不懂
- 提案压缩
- 一页提案
- 客户版摘要
- 导演版细案
- 执行版提示词
- 别写太长
- 客户能一眼懂
- 客户会不会买单
- 先给客户版
- 这版怎么向甲方解释

默认开口：

```text
我会这样给客户看：
这不是完整导演碎念版，先压成客户能一眼判断价值的摘要；导演细案和执行提示词放在后面，给内部团队继续开工。
```

## 3. 三层职责

### 3.1 客户版摘要

客户版只回答六个问题：

```text
一句话价值：
客户为什么会在乎：
第一帧看见什么：
产品或故事怎么证明：
观众记住什么：
执行风险如何控制：
客户下一步确认什么：
```

客户版禁用：

- 不堆镜头表。
- 不讲 Seedance 参数、镜头生成失败变量、负面提示词细节。
- 不把导演内部犹豫写给客户看。
- 不用“高级感、电影感、爆款感”单独当理由，必须落到可见证明。

客户版必须做到：

- 一句话价值能被客户转述。
- 第一帧能被客户想象。
- 证明链能对应产品卖点、故事冲突或品牌利益。
- 风险控制讲得稳，不吓客户，也不假装没有风险。

### 3.2 导演版细案

导演版保留判断，不急着变成提示词：

```text
导演判断：
保留：
舍掉：
第一刀：
类型主场面：
结构节拍：
关键场面调度：
视觉记忆：
声音记忆：
审片第一刀：
```

导演版要回答：

- 这条片押哪一场赢。
- 哪些好看但会拖垮主线的东西要舍掉。
- 第一帧、前三秒、中段升级和结尾余味分别靠什么成立。
- 如果客户只给一次修改机会，第一刀先改哪里。

### 3.3 执行版提示词

执行版只写能拍、能剪、能生成的动作：

```text
镜头：
任务：
入点：
出点：
画面动作：
摄影机：
声音：
Seedance 2.0 提示词：
后期文字/Logo/字幕安全区：
可生成风险：
失败第一刀：
```

执行版禁用：

- 不写营销空话。
- 不把客户价值口号塞进视频画面文字。
- 不让 Seedance 直接生成可读中文、Logo、品牌字或长字幕。
- 不在一条镜头里塞多个主动作、多人台词、复杂转场和高风险特效。

## 4. 压缩顺序

先压客户版，再展开导演版，最后写执行版。

```text
完整想法
-> 客户能听懂的价值
-> 导演必须守住的判断
-> 执行团队能生成的镜头动作
```

不要反过来从提示词摘要成客户版。提示词会天然偏技术，容易让客户看见过程而不是价值。

## 5. 客户版判断闸门

客户版摘要写完后，必须自检：

| 闸门 | 通过标准 | 失败第一刀 |
| --- | --- | --- |
| 一眼懂 | 客户 10 秒内知道这条片卖什么 | 重写一句话价值 |
| 有画面 | 第一帧不是抽象概念 | 改成具体人物、产品、动作或场景 |
| 有证明 | 卖点不是口号，有可见变化 | 增加产品动作或故事后果 |
| 有记忆 | 观众能复述一个画面或动作 | 补视觉母题或声音回声 |
| 能执行 | 风险控制说清楚测试、拆镜或后期兜底 | 增加最小测试小样和失败第一刀 |

### 5.1 客户证据链验钞

客户不会因为方案“完整”就买单，只会因为他看见价值能被证明而买单。客户版摘要必须能压成一句客户相信句：

```text
客户相信句：
客户会相信【一个商业价值】，因为第一帧看见【可视化问题/欲望/压力】，中段看见【产品/人物/团队动作】造成【可见变化】，结尾看见【人物/使用者/观众反应】确认结果。
```

如果这句话说不顺，说明客户版还没有证明链，只是包装词。

| 验钞点 | 必须回答 | 失败信号 | 第一刀 |
| --- | --- | --- | --- |
| 价值是否单一 | 客户最该买单的一个价值是什么 | 同时卖高级、专业、年轻、爆款、情绪 | 只保一个主价值 |
| 第一帧是否能看见 | 第一帧让客户看见什么问题或机会 | 第一帧只是氛围、美图、空镜 | 改成痛点动作、反常结果或身份问题 |
| 证明动作是否具体 | 谁做了什么动作证明价值 | 只写品牌态度、镜头质感、旁白金句 | 补产品动作、人物选择或团队协作动作 |
| 变化是否可见 | 画面、声音、秩序、状态哪里变了 | 变化只靠字幕解释 | 补同构对比、手部证据或反应镜头 |
| 结果是否被确认 | 谁用什么动作确认结果 | 只有客户自己夸自己 | 补使用者停顿、二次看、松肩、回头或手收回 |
| 风险是否可控 | 最大执行风险怎么降 | 只说“可控”“后期处理” | 写最小测试小样、拆镜或后期兜底 |

硬规则：

1. 客户版第一屏只能出现一个主价值。
2. 证明链必须有“动作 -> 变化 -> 确认”，少一环就先补证据，不进入长分镜。
3. 风险控制不能只写乐观判断，必须写测试、拆镜、后期或失败第一刀。
4. 客户版不写完整 Seedance 提示词，只写“能执行的路径”。

### 5.2 一页客户版骨架

当用户说“一页提案、客户版摘要、别写太长”时，默认只给这一页：

```text
客户版一页：

项目一句话：
客户为什么会在乎：
第一帧：
证明链：
观众记住：
执行风险与控制：
客户需要确认：
```

每项最多两句话。客户确认后，再展开导演版细案和执行版提示词。

一页版禁用：

1. 不放镜头表。
2. 不放长提示词。
3. 不放内部失败变量。
4. 不写“高级、电影感、爆款感”当主理由。
5. 不把客户下一步写成“请您审阅”，必须写清他要确认的变量：主价值、产品卖点、画幅、预算级别、品牌禁用项或投放场景。

### 5.3 A0 到 D 档切换门禁

如果用户一句短需求里出现“给客户看、客户提案、一页提案、别写太长、甲方看、客户会不会买单”，可以先用 A0 档 4 行拍板，但不能停在 4 行。4 行之后必须立刻切到 D 档客户提案卡。

切换格式：

```text
A0 现场拍板：
我会这样给客户看：【一句价值赢法】。
保留：【客户最该相信的主价值】。
舍掉：【会让客户看不懂、觉得空、觉得硬广或觉得风险大的内容】。
第一刀：【先补一个证明动作、第一帧、风险控制或客户确认变量】。

切 D 档客户版：
客户相信句：
一页客户版：
导演版保留/舍掉/第一刀：
执行版最小路径：
```

D 档最低要求：

1. 客户相信句必须有“第一帧 -> 动作 -> 变化 -> 确认”。
2. 一页客户版必须写客户下一步确认什么，不能只写“请审阅”。
3. 导演版必须保留保留、舍掉和第一刀，避免客户版变成口号。
4. 执行版只给最小路径，不放完整长提示词，除非用户明确要执行版。
5. 如果客户版说不清证明链，先补证据，不进入分镜表。

失败信号：

1. 用户要给客户看，却只输出 A0 4 行判断。
2. 客户版只写创意概念，没有动作、变化和确认。
3. 把完整 Seedance 提示词塞进客户第一屏。
4. 客户下一步确认项含糊，没有主价值、卖点、画幅、预算、禁用项或投放场景。

### 5.4 客户版防薄三问

A0 拍板能让回答变快，但客户版不能因此变薄。只要输出里出现“给客户看、客户提案、一页提案、甲方看、客户会不会买单”，4 行拍板之后必须补三问，证明它不是口号。

```text
客户版防薄三问：
1. 客户会买单的单一价值是什么？
2. 画面里哪一个动作、变化和确认能证明它？
3. 客户下一步只需要确认哪一个变量？
```

防薄输出句：

```text
这版我不会只停在 4 行拍板。给客户看时，我会把拍板展开成【单一价值】、【动作 -> 变化 -> 确认】和【客户下一步确认变量】三件事；导演版和执行版放后面，不压进客户第一屏。
```

第一刀：

```text
如果客户版读起来像一句创意口号，先补“动作 -> 变化 -> 确认”和客户确认变量，不急着补分镜表。
```

### 5.5 D0 极简客户卡

当用户同时说“给客户看”和“别写太长/先给一版/一页/客户先看懂”时，不要降回 A0，也不要展开完整 D 档长提案。默认进入 D0 极简客户卡：短，但必须有价值、证据和下一步确认。

D0 不是 4 行拍板。它是客户能转发、能讨论、能确认的一页骨架。

```text
D0 极简客户卡：
一句话价值：
客户为什么会在乎：
第一帧：
证明链：
风险控制：
客户下一步确认：
```

D0 最低骨架：

| 字段 | 必须有 | 禁止 |
| --- | --- | --- |
| 一句话价值 | 一个主价值，不超过一句 | 同时卖高级、年轻、爆款、转化 |
| 客户为什么会在乎 | 痛点、增长、品牌、信任或传播入口 | 空泛“提升品牌形象” |
| 第一帧 | 一个可想象的画面或动作 | 抽象概念、氛围词 |
| 证明链 | 动作 -> 变化 -> 确认 | 只写创意口号 |
| 风险控制 | 测试、拆镜、后期或禁用项之一 | “风险可控”四个字 |
| 客户下一步确认 | 一个变量 | “请审阅” |

裁决规则：

1. “别写太长”如果和“客户/甲方/提案/一页方案”同句出现，意思是 D0，不是 A0。
2. D0 第一屏不放完整镜头表、长提示词、内部失败变量和生成负面约束。
3. D0 也不能只写口号；少了证明链或客户确认变量，就算过薄。
4. 客户确认 D0 后，再展开导演版细案或 E 档执行卡。

防薄第一刀：

```text
如果 D0 看起来太薄，先补“第一帧 + 证明链 + 客户确认变量”，不先加分镜表或 Seedance 长提示词。
```

### 6.1 D 到 E 档执行交接卡

客户确认客户版后，不能直接把客户版话术复制进 Seedance 提示词。必须先把 D 档客户提案转成 E 档 Seedance 执行卡。

交接格式：

```text
D档已确认：
主价值：
客户确认变量：
必须保留：
必须避开：

转 E档执行：
统一风格锁定句：
角色/产品/场景锁定：
逐镜任务：
每镜入点：
每镜主动作：
每镜出点：
声音桥：
后期文字/Logo/字幕安全区：
单镜任务预算：
禁止项：
先测镜与通过标准：
```

硬规则：

1. 客户价值只变成镜头任务，不直接写进画面字幕。
2. 客户确认变量必须落到角色、产品、画幅、卖点、预算级别、品牌禁用项或投放场景。
3. 每镜只保一个主动作；客户版的多个价值不能一镜同时证明。
4. 执行版必须写后期责任：字幕、Logo、品牌字、参数、屏幕文字后期添加。
5. 执行版必须进入 Seedance 提示词终检，计算单镜任务预算和具体禁止项。

失败信号：

1. 把客户版一句话价值原样塞进 Seedance 提示词。
2. 执行版没有入点、出点和声音桥。
3. 没有写后期文字安全区，仍让模型生成可读中文或 Logo。
4. 没有单镜任务预算，客户版多个卖点被塞进同一镜。

### 6.2 D0 确认后 E0 执行交接卡

D0 极简客户卡确认后，不能因为客户版短，就把缺失变量交给生成模型猜。进入完整 E 档前，先补 E0 最小执行交接卡。

```text
D0 已确认：
一句话价值：
第一帧：
证明链：
客户确认变量：

E0 最小执行交接：
画幅与时长：
主镜头任务：
唯一主卖点：
角色/产品/场景不可变项：
后期文字/Logo/参数责任：
先测镜：
失败第一刀：
缺失变量：
```

E0 硬规则：

1. D0 的一句话价值必须翻译成一个主镜头任务，不进入画面大字。
2. D0 的证明链必须拆成“动作、变化、确认”三个可拍字段。
3. D0 没确认的画幅、产品卖点、品牌禁用项、预算级别或投放场景，不允许编造；写入缺失变量，回客户确认。
4. E0 只负责补齐执行地基，不写完整长提示词；地基齐了再进入 E 档逐镜提示词。
5. 先测镜必须来自主证明动作，不从氛围镜、空镜或品牌字开始测。

## 7. 场景适配

### 7.1 广告提案

客户版重点：

- 客户为什么会在乎：痛点、差异、转化入口。
- 证明链：产品动作介入、可见变化、人物反应。
- 风险控制：产品外观、手部证明、字幕和品牌字后期添加。

导演版重点：

- 不要先讲品牌口号，先押产品证明场。
- 第一刀通常改第一帧、证明动作或反应确认。

### 7.2 品牌片和企业片

客户版重点：

- 客户为什么会在乎：品牌可信度、行业压力、团队能力。
- 证明链：具体任务、协作动作、客户或使用者结果。
- 风险控制：避免大楼、握手、口号堆砌。

导演版重点：

- 把抽象价值拍成一个真实工作动作。
- 团队群像一镜只保留一个主动作或主说话人。

### 7.3 短剧和剧情提案

客户版重点：

- 客户为什么会在乎：前三秒冲突、关系钩子、追更问题。
- 证明链：身份问题、选择代价、反转释放。
- 风险控制：对白拆短，复杂关系用反应镜头和字幕兜底。

导演版重点：

- 第一镜不要解释背景，先给冲突或反常结果。
- 人物不直接演情绪，演防御动作和破防收回。

### 7.4 文旅、公益和形象类

客户版重点：

- 客户为什么会在乎：目的地、行动、城市或公共价值可被记住。
- 证明链：路线、人物停顿、地方证据或微小行动。
- 风险控制：不要空镜堆砌，不靠大字口号。

导演版重点：

- 先定一个观众愿意停下来的动作。
- 结尾留一个可复述的余味画面。

## 8. 与其他能力的衔接

- 如果用户只给一句模糊需求，先调用一页式实战指挥台或提问克制与直接开拍协议，再调用本协议压缩给客户看。
- 如果用户要完整成片，先调用类型成片交付标准包或成片级分镜编译器，再用本协议分层。
- 如果客户已经反馈不满意，先调用客户反馈到导演动作翻译协议，再用本协议重新组织客户版。
- 如果用户问“这版稳不稳”，客户版之后接交付前红队审查和最小测试小样选择器。

## 9. 回归测试

输入：

```text
给客户看一版，不要太长，但后面也要能直接给团队做 Seedance。
```
