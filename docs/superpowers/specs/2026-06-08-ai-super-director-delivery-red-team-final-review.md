# AI超级导演交付前红队审查与防翻车协议

## 1. 定位

这份协议用于完整方案、客户提案、发布包装、整条 Seedance 项目或最终交付前的最后一遍反向审查。它不负责把方案写漂亮，而是故意站在最挑剔的客户、普通观众、剪辑师、生成模型和合规审查的角度，提前找出最可能翻车的地方。

一句话原则：

```text
交付前先让反方挑错。
能被客户误解、观众看不懂、模型生成坏、剪辑接不上、合规卡住的地方，先在交付前改掉。
```

它和相邻能力的分工：

1. 不出错工具化防错协议：负责全流程高概率错误门禁。
2. 输出审片评分与升级闸门：负责给方案质量打分和第一刀升级。
3. 项目交付包与输出模板库：负责交付项是否完整。
4. 本协议：负责最终交付前的红队反审，找“别人会怎么挑刺”。

## 2. 触发信号

当用户出现以下说法时，默认调用本协议：

1. “给客户看之前再检查一遍”。
2. “最终版、交付版、提案版、发布前最后检查”。
3. “这版有没有硬伤、会不会被客户挑刺”。
4. “有没有哪里容易翻车、哪里容易被误解”。
5. “帮我像甲方/观众/剪辑/生成模型一样挑错”。
6. “我要发出去了，最后帮我把关”。

如果只是普通方案升级，先走输出审片评分与升级闸门。  
如果已经有生成结果，先走生成后回放验片与剪辑救援协议。  
如果红队发现主结构错误，再进入导演改稿手术。

## 3. 六个红队视角

交付前必须从六个视角各看一遍，不要只看创意好不好。

| 红队视角 | 它会挑什么 | 必须回答 |
| --- | --- | --- |
| 客户视角 | 价值不清、执行不清、风险不清 | 客户看完知道为什么做、怎么做、交付什么吗 |
| 普通观众视角 | 开头慢、看不懂、记不住 | 三秒内能懂一个问题，结尾能复述一个点吗 |
| 剪辑师视角 | 镜头接不上、缺反应、缺插入 | 有主镜头、反应镜、证明镜和保底出点吗 |
| 生成模型视角 | 一镜任务过载、文字乱码、角色漂 | 每镜能独立生成，风险镜已降难吗 |
| 合规视角 | 真实品牌/IP/功效/绝对化话术风险 | 有没有复刻、虚假承诺、错误 Logo 或不可证实说法 |
| 发布视角 | 标题封面弱、平台不适配、互动廉价 | 第一帧、标题、封面和评论入口是否服务目标 |

## 4. 红队审查顺序

按这个顺序审，不要先陷入措辞：

1. 目标是否明确：这次交付到底要客户通过、观众观看、平台发布，还是进入生成？
2. 第一眼是否成立：标题、第一帧、核心策略或项目名是否让人知道在看什么？
3. 主链是否清楚：观众能否复述“谁遇到什么问题，发生了什么变化”？
4. 证明是否可见：广告卖点、情绪变化、人物选择或产品价值有没有动作证据？
5. 镜头是否能剪：有没有入点、出点、反应、插入、声音桥和保底镜？
6. Seedance 是否能跑：高风险镜头是否拆开，文字和 Logo 是否后期处理？
7. 客户是否能执行：交付项、流程、下一步确认和风险边界是否清楚？
8. 发布是否能站住：标题封面、前三秒、评论点和平台语气是否匹配？
9. 合规是否有红线：真实人物、品牌、医疗金融功效、IP参考是否被安全处理？

## 5. 常见翻车点与第一刀

| 翻车点 | 表现 | 第一刀 |
| --- | --- | --- |
| 客户只觉得好看 | 没有业务目标、卖点证明或执行路径 | 加项目目标、证明镜头和交付清单 |
| 观众看不懂 | 第一镜铺背景，中段信息散 | 改第一帧问题，删掉一条副线 |
| 广告像口号 | 卖点是形容词，没有动作证据 | 改成痛点、产品动作、结果变化 |
| 短剧像梗概 | 冲突来得晚，人物没有选择代价 | 第一场直接给阻碍者和被迫选择 |
| 分镜剪不起来 | 全是主镜，没有反应或插入 | 补反应保险、手部证据、声音桥 |
| Seedance 跑不稳 | 一镜多人物、长台词、复杂运镜和特效 | 拆镜，保主动作，降运镜 |
| 文字和 Logo 出错 | 让模型直接生成中文或品牌字 | 后期添加，画面只留干净安全区 |
| 客户会挑合规 | 绝对化功效、真实品牌/IP相似 | 换成可证实表达和原创替换 |
| 发布包装虚 | 标题复述内容，封面没有问题 | 标题抛问题，封面抓反常一帧 |
| 方案太满 | 所有能力都展开，主目标被淹没 | 定主目标，删掉非必要模块 |

## 6. 客户误读场景模拟

红队不能只说“这里可能不清楚”，必须模拟一个真实误读句。

默认做六个误读角色：

| 误读角色 | 容易误读成 | 预演句式 | 第一刀 |
| --- | --- | --- | --- |
| 客户负责人 | 以为这是审美方案，不知道商业价值 | “所以这条片主要是好看，但卖点怎么证明？” | 补一句业务目标和一镜证据 |
| 普通观众 | 以为是背景介绍，看不出主问题 | “我看懂氛围了，但不知道谁遇到什么事。” | 改第一帧问题和主动作 |
| 剪辑师 | 以为每镜都必须保留，找不到主镜 | “哪些是主镜，哪些只是补镜？” | 标主镜、反应镜、桥镜和可删镜 |
| 生成模型 | 把文字、Logo、长台词或多人动作硬生成 | “这一镜会同时生成字幕、口型、多人动作和复杂运镜。” | 拆镜，文字后期，保一个主动作 |
| 合规/法务 | 以为在承诺功效、复刻参考或使用真实品牌资产 | “这句话能不能被证明？这个参考会不会太像？” | 换可证实表达和原创替换 |
| 发布运营 | 以为标题封面只能复述主题 | “封面没有问题感，评论区也接不上话。” | 重选截图帧，绑定评论问题 |

误读模拟的输出必须短而具体：

```text
最可能误读的人：
【客户 / 观众 / 剪辑 / 生成 / 合规 / 发布】

他会误读成：
“【一句真实会说出口的话】”

根因：
【目标不清 / 第一帧不清 / 主镜不清 / 证据不清 / 生成过载 / 合规边界不清 / 发布钩子弱】

第一刀：
【只改一个镜头、证明、标题、封面、提示词边界或后期说明】
```

判断句：

```text
交付前不是证明我写得多完整，而是证明别人不会把它读歪。
只要一个关键人会误读，先改误读源头，不靠后面解释补救。
```

## 7. 红队结论分级

| 结论 | 判断 | 处理 |
| --- | --- | --- |
| 可交付 | 只有小措辞或格式问题 | 直接交付，保留风险提示 |
| 小修后交付 | 主链成立，有 1-2 个弱项 | 只改弱项，不重写全案 |
| 先补证据 | 创意成立，但证明链不够 | 补产品动作、人物反应或证据镜 |
| 先降生成风险 | 方案成立，但镜头过载 | 拆镜、降运镜、短台词、文字后期 |
| 先改主结构 | 第一帧、主链或目标错 | 进入导演改稿手术，不急着交付 |
| 暂不交付 | 合规、品牌、事实或客户目标不明 | 先确认或改成安全替代方案 |

判断句：

```text
不要把所有问题都当成重写问题。
小修、小补证据、降风险、改主结构和暂不交付，必须分开判断。
```

## 9. 红队禁忌

1. 不要为了显得严格，把可交付方案判成重写。
2. 不要只挑措辞，不挑主链、证据、生成和合规。
3. 不要一次要求改十个方向。
4. 不要用“更高级、更电影感、更爆”代替具体第一刀。
5. 不要承诺“客户一定满意”或“发布一定爆”。
6. 不要为了安全，把作品改得没有记忆点。
7. 不要把所有合规风险都推给用户，能原创替换的先给替代方案。
8. 不要把“别人会误读”写成抽象担心，必须写成一句真实误读话。

## 10. 与其他能力衔接

如果红队发现“主目标不清”，回到一页式实战指挥台或现场判断中枢。  
如果发现“交付项缺失”，进入项目交付包与输出模板库。  
如果发现“质量弱但方向对”，进入输出审片评分与升级闸门。  
如果发现“镜头过载”，进入 Seedance 镜头可生成性、难度评分与拆镜决策库。  
如果发现“已经生成的素材有瑕疵”，进入生成后回放验片与剪辑救援协议。  
如果发现“参考对象太像”，进入参考作品拆解、原创替换与合规转译闸门。  
如果发现“整条方案需要重排”，进入导演改稿手术与方案升级引擎。

## 11. 最小合格线

交付前红队审查至少要给出：

1. 红队结论。
2. 最危险的一处。
3. 客户视角问题。
4. 观众视角问题。
5. 生成或剪辑风险。
6. 最可能的误读。
7. 第一刀。
8. 交付前通过标准。

少一项，就不是最后把关，只是又做了一次普通点评。
