# AI超级导演经验回写与版本进化协议

## 1. 定位

这份协议让 AI超级导演不只是当场把一个方案写好，而是能把每次试拍、返工、审片、客户反馈、优秀样例和失败案例，回写成下一次可调用的能力。

它不替代作品复盘与成长系统，也不替代自我校准回归测试。复盘负责看见问题，回归测试负责检查退化；本协议负责决定“这条经验应该写回哪里，写成什么形态，怎么防止能力库越写越厚但输出没变强”。

一句话原则：

```text
一次经验如果不能改变下一次输出，就不算进化。
```

## 2. 什么时候必须回写

遇到以下情况，默认触发经验回写：

1. 同一类错误出现第二次，例如口型穿帮、群像融合、动作看不清、客户觉得空。
2. 某个镜头试生成失败，但原因被明确定位。
3. 某个输出被用户评价“像真人导演、有用、能直接拍”。
4. 某个参考作品被成功转译成原创方法。
5. 某个类型出现新打法，例如可爱广告、特摄短剧、B2B品牌片、AI短片新趋势。
6. 新增能力后，回归题暴露弱点。
7. 客户提案或发布前检查发现交付漏项。

不用回写的情况：

1. 只是一次性偏好，没有可复用价值。
2. 只是换措辞，没有改变判断、拆镜、生成或交付。
3. 问题来自用户明确临时要求，不适合作为默认规则。
4. 经验无法写成可检查标准。

## 3. 经验回写路由表

| 经验类型 | 写回位置 | 写成什么 |
| --- | --- | --- |
| 路由错 | 一键响应内核 / 一页式实战指挥台 / 能力调用仲裁器 | 新触发词、优先级或仲裁规则 |
| 输出太长或太短 | 输出档位与场合切换器 | 档位选择规则和反例 |
| 问太多 | 提问克制协议 | 必问/不问边界 |
| AI腔或模板感 | 活人导演人格校准器 / 反模式黑名单 | 坏写法和第一刀改法 |
| 审美跑偏 | 审美取舍罗盘 | 主审美、禁用项、第一帧气质 |
| Seedance 失败 | 可生成性拆镜库 / 返工迭代协议 / 防错协议 | 风险信号、拆镜策略、通过标准 |
| 客户不买单 | 项目交付包 / 广告证明链 / 输出审片闸门 | 漏项清单、证明镜头、客户语言 |
| 好样例 | 黄金样例基准包 | 标准输入、黄金开口、合格线、错误写法 |
| 反复失败 | 自我校准回归测试套件 | 新回归题和通过标准 |
| 新类型方法 | 对应类型引擎 / 类型公式手册 | 类型公式、第一镜、禁用项、Seedance 卡 |
| 参考作品精华 | 跨类型导演精华吸收实验室 | 导演 DNA 卡和原创替换规则 |

## 4. 回写格式

每条经验必须压成 6 个字段：

```text
触发场景：
用户或作品里出现什么信号？

问题或亮点：
具体好在哪里，或具体坏在哪里？

导演判断：
下次遇到时先判断什么？

第一刀：
下次第一步改什么、保什么或删什么？

写回位置：
应该进入哪一张能力卡？

可检查标准：
下次怎样证明它真的被用上了？
```

禁止只写感想：

```text
以后要更有电影感。
以后要更自然。
以后要更高级。
```

这些都不能回写。必须改成动作、触发词、规则、模板、测试题或禁用项。

## 5. 五种回写动作

### 5.1 加入口

适合：用户说法没有被正确识别。

写法：

```text
当需求出现【触发词】时，默认调用【能力】。
```

例：

```text
当用户说“别问太多、先给一版、按你判断”时，默认调用提问克制与直接开拍协议。
```

### 5.2 加禁用项

适合：高概率错误需要被拦住。

写法：

```text
遇到【场景】时，禁止【坏做法】，改为【稳做法】。
```

例：

```text
遇到多人会议短剧，禁止一镜多人同时说长台词，改为主说话人、反应镜和插入证据。
```

### 5.3 加第一刀

适合：同类失败有明确修法。

写法：

```text
如果【症状】，第一刀先【动作】，不要同时改【变量】。
```

例：

```text
如果角色漂且动作乱，第一刀先锁角色和动作起点，不同时升级运镜。
```

### 5.4 加黄金样例

适合：某次输出达到高标准，可以作为对照。

必须包含：

1. 输入。
2. 黄金开口。
3. 成片骨架。
4. 合格线。
5. 错误写法。

### 5.5 加回归题

适合：新问题可能反复退化。

必须包含：

1. 输入题。
2. 必须触发的能力。
3. 通过标准。
4. 常见失败。
5. 低于 4 分的第一刀修正。

## 6. 回写优先级

不是所有经验都值得立刻新增文档。按优先级处理：

1. 高频错误优先。
2. 会导致生成失败的错误优先。
3. 会导致客户交付失败的漏项优先。
4. 能显著提升真人导演感的样例优先。
5. 能转成回归测试的经验优先。
6. 只影响措辞的小偏好延后。

判断句：

```text
这条经验如果不写回，下次会不会再错？
```

如果答案不是“会”，可以不写回。

## 7. 防止能力库膨胀

每次回写前做三项检查：

1. 是否已有文档能承载？优先补现有卡，不急着新增卡。
2. 是否能写成可检查标准？不能检查就不写。
3. 是否会改变下一次输出？不会改变就不写。

新增文档只在以下情况成立：

1. 现有能力没有入口。
2. 现有能力之间有冲突需要仲裁。
3. 经验跨多个类型，值得成为通用协议。
4. 经验已经出现多次，单点补丁不够。

## 8. 回写后的验证

每次回写后，必须做三件事：

1. 链接验证：README 能找到新入口，且本地链接不坏。
2. 完整性验证：不出现未完成标记。
3. 行为验证：至少写出一条“下次遇到什么会触发它”。

如果新增的是高层能力，还要补一条回归题或黄金样例。  
如果只是小补丁，至少补一个触发句或禁用项。

## 9. 写回后的调用契约

经验写回不是把内容放进文档，而是让下一次输出自动变样。

每条写回经验必须补齐四个契约：

| 契约 | 必须写清 | 不合格表现 |
| --- | --- | --- |
| 触发契约 | 下次用户、素材或方案出现什么信号会调用它 | 只写“以后注意” |
| 输出契约 | 被调用后第一句话、第一刀、分镜或提示词会多出什么 | 只写在文档里，输出没变化 |
| 禁用契约 | 下次同场景禁止哪种旧反应 | 仍然允许旧错复发 |
| 验证契约 | 用什么关键词、回归题或通过标准证明它被用上 | 没有可检查证据 |

写法：

```text
触发契约：
当出现【触发信号】时，先调用【能力/规则】。

输出契约：
输出里必须出现【导演判断 / 第一刀 / 禁用项 / 通过标准 / Seedance 拆镜字段】。

禁用契约：
禁止继续【旧坏反应】。

验证契约：
用【关键词 / 回归题 / 小样通过标准】证明这条经验生效。
```

示例：

```text
触发契约：
当客户说“Logo 再大一点、卖点都说出来、照参考再像一点”时，先调用客户反馈去伪存真。

输出契约：
必须区分硬性事实、真实担心、表面词和有害字面要求，并给替代导演动作。

禁用契约：
禁止照字面堆 Logo、堆卖点和复刻参考外壳。

验证契约：
客户反馈输出里必须出现“有害字面要求”和“替代导演动作”。
```

判断句：

```text
如果写回后，下次输出看不出任何变化，这条经验就没有真正进入能力系统。
```

## 10. 回写示例

### 10.1 Seedance 失败

```text
触发场景：
用户说“角色漂了，动作也乱，再跑一版”。

问题或亮点：
提示词同时要求角色稳定、走位、情绪变化、复杂推轨和道具特写。

导演判断：
这是单镜任务过载，不是单纯提示词不够细。

第一刀：
本轮只锁角色和动作起点，先不升级运镜。

写回位置：
Seedance 2.0 返工迭代协议、反模式黑名单。

可检查标准：
新提示词必须写“本轮只改一个变量”，并列出必须锁住、必须删掉和通过标准。
```

### 10.2 客户提案失败

```text
触发场景：
客户觉得方案漂亮但不知道产品怎么卖。

问题或亮点：
广告审美强，但缺少产品动作和可见结果。

导演判断：
商业证明让位给了视觉空镜。

第一刀：
先补痛点、产品动作、结果变化和人物确认。

写回位置：
创意广告证明链、能力调用仲裁器、项目交付包。

可检查标准：
客户提案里必须出现产品证明镜头，而不是只有品牌气质。
```

### 10.3 好样例沉淀

```text
触发场景：
某条可爱治愈广告输出被确认“能直接拍”。

问题或亮点：
小主体大任务、产品动作、反应停顿和封面帧都成立。

导演判断：
可爱来自任务压力，不来自堆萌词。

第一刀：
下次可爱广告先找小主体的大任务。

写回位置：
黄金样例基准包、可爱治愈导演引擎。

可检查标准：
可爱广告必须有小主体大任务或微小伤口，不能只有萌物摆拍。
```

## 11. 最小合格线

一次经验回写至少要做到：

1. 说明触发场景。
2. 说明问题或亮点。
3. 写出导演判断。
4. 写出第一刀。
5. 指定写回位置。
6. 写出可检查标准。
7. 写出触发契约、输出契约、禁用契约和验证契约。

少一项，就只是复盘感想，不是能力进化。
