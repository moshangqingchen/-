# AI超级导演成片版本管理与 A/B 决策协议

## 1. 定位

这份协议解决多版本混乱的问题。短片、短剧、广告和 Seedance 项目经常会出现多个开头、封面、标题、主镜头、产品证明、结尾和客户版。AI超级导演不能只说“都不错”，要判断哪个版本用于客户交付，哪个用于发布测试，哪个只适合内部验证，哪个应该被淘汰。

它不替代平台发布与爆款包装库。发布库负责标题、封面、简介和评论区；本协议负责版本命名、变量控制、A/B 选择、客户版与发布版分流、失败回滚和复盘写回。

一句话原则：

```text
版本不是越多越好。每个版本必须只回答一个问题。
```

默认目标：

1. 多版本有命名、有用途、有主变量。
2. 客户安全版和传播测试版分开，不互相污染。
3. A/B 测试只改一个变量，避免失败后无法判断原因。
4. 版本选择有通过标准，不靠临场感觉。
5. 失败版本能回滚，优秀版本能写回方法库。

## 2. 什么时候必须启用

遇到以下信号，默认调用本协议：

1. 用户说“做几个版本、A/B、哪个版本更好、选哪个、客户版和发布版、封面版本、标题版本、开头版本、结尾版本”。
2. 同一条片出现多个第一帧、多个前三秒、多个主镜头或多个产品证明方案。
3. 客户提案需要保守版和创意版并存。
4. 发布前需要测试封面、标题、前三秒或结尾互动。
5. Seedance 生成出多个可用素材，需要决定保留、剪救、重跑或替换。
6. 团队内部意见分裂，无法判断哪版更符合主目标。

不必启用的情况：

1. 只有一个明确方向，且用户要快速输出。
2. 修改只是错别字、字幕、品牌字位置或法务硬要求。
3. 用户明确只要一个最终版，不需要测试策略。

## 3. 版本类型

| 版本类型 | 目的 | 适合场景 | 判断标准 |
| --- | --- | --- | --- |
| 导演推荐版 | 最符合作品赢法 | 创意定稿、内部拍板 | 第一帧、主场面、余味和生成稳定性平衡最好 |
| 客户安全版 | 降低误读和验收风险 | 提案、交付、品牌方审阅 | 卖点清楚、品牌安全、合规低风险 |
| 传播测试版 | 测试停留、标题、封面、前三秒 | 发布前包装 | 只改一个传播变量 |
| 生成稳定版 | 降低 Seedance 翻车 | 高风险镜头、角色连续性 | 角色、动作、口型和文字风险最低 |
| 情绪加强版 | 强化共鸣、余味、人物反应 | 治愈、怀旧、公益、品牌故事 | 人物动作更真，结尾更能停住 |
| 转化加强版 | 强化产品证明和行动入口 | 广告、种草、带货、企业服务 | 痛点、产品动作、结果变化更清楚 |
| 实验版 | 尝试新风格、新结构或新镜头 | 内部探索、导演成长 | 可失败，不直接交付客户 |
| 回滚版 | 保留上一版最稳骨架 | 连续失败后的保底 | 能剪、能交付、风险可控 |

## 4. 版本命名规则

每个版本都要能从名字看出用途：

```text
项目名_版本类型_主变量_日期
```

示例：

```text
咖啡广告_客户安全版_产品证明_0608
咖啡广告_传播测试版_第一帧异常_0608
幼儿园短片_导演推荐版_群像反应_0608
旧物情感片_情绪加强版_结尾留白_0608
特效短剧_生成稳定版_接触受力_0608
```

禁止命名：

```text
最终版
最终最终版
最新版
改好版
客户版2
再试试版
```

这些名字无法判断变量，也无法复盘。

## 5. A/B 决策变量

一次只测一个变量。

| 可测试变量 | A 版 | B 版 | 不要同时改 |
| --- | --- | --- | --- |
| 第一帧 | 异常结果 | 人物强反应 | 不同时改角色和风格 |
| 前三秒 | 台词冲突 | 动作中点 | 不同时改结尾 |
| 主镜头 | 产品证明 | 人物反应 | 不同时改卖点 |
| 封面 | 人物表情 | 关键道具 | 不同时改标题方向 |
| 标题 | 问题型 | 情绪型 | 不同时改封面主体 |
| 结尾 | 情绪余味 | 下一集悬念 | 不同时改中段结构 |
| 声音入口 | 第一声异常 | 环境声压迫 | 不同时改画面信息 |
| 品牌露出 | 后期品牌字 | 产品动作入画 | 不同时改主故事 |

错误测试：

```text
A版换开头、标题、封面、节奏和结尾。
B版换角色、色彩、台词、产品动作和声音。
```

这种对比不能说明哪一个变量有效。

## 6. 版本选择顺序

先定主目标，再选版本：

```text
客户过审
-> 客户安全版优先

平台传播
-> 传播测试版优先

生成稳定
-> 生成稳定版优先

导演作品感
-> 导演推荐版优先

产品转化
-> 转化加强版优先

情绪共鸣
-> 情绪加强版优先
```

拍板问题：

1. 这版解决的主目标是什么？
2. 这版只改了哪个变量？
3. 这版牺牲了什么？
4. 这版最可能在哪里翻车？
5. 如果失败，回滚到哪个版本？

## 7. 客户版与发布版分流

客户版默认更稳：

1. 卖点更清楚。
2. 合规风险更低。
3. 字幕、品牌字、产品动作更明确。
4. 不靠容易误解的反讽、擦边、夸张承诺。
5. 可生成性和剪辑连续性更高。

发布版可以更抓人：

1. 第一帧更反常。
2. 标题问题感更强。
3. 前三秒信息债更明显。
4. 结尾更适合评论或追更。
5. 但不能牺牲事实、合规和品牌底线。

分流句：

```text
我会给客户看 A 版，因为它把卖点和品牌风险讲清楚；发布先测 B 版，因为它的第一帧更能让陌生观众停住。两个版本的核心创意不变，只分流包装和信息释放。
```

## 8. 多版本拍板卡

默认输出格式：

```text
我会这样拍板：

主目标：
【客户过审 / 发布传播 / 生成稳定 / 产品转化 / 情绪共鸣 / 导演作品感】

版本表：
| 版本 | 用途 | 主变量 | 优点 | 风险 | 去向 |
| --- | --- | --- | --- | --- | --- |
| A版 |  |  |  |  |  |
| B版 |  |  |  |  |  |

导演推荐：
【选哪版作为主版本】

客户版：
【给客户看哪版，为什么】

发布测试版：
【发布先测哪版，为什么】

```

## 9. 不同项目的版本策略

### 9.1 创意广告

优先版本：

1. 客户安全版：产品证明清楚。
2. 传播测试版：第一帧痛点更强。
3. 转化加强版：行动入口更明确。

不建议：

1. 为了抓眼把卖点改虚。
2. 为了高级删掉产品动作。
3. 为了年轻感加无关段子。

### 9.2 短剧

优先版本：

1. 导演推荐版：冲突换手最清楚。
2. 传播测试版：前三秒身份问题更强。
3. 生成稳定版：口型和站位风险更低。

不建议：

1. 同时测试反转、角色、台词和结尾。
2. 为了悬念让观众完全看不懂。
3. 让多人同框长对白承担测试。

### 9.3 可爱治愈

优先版本：

1. 情绪加强版：小主体反应更真。
2. 传播测试版：封面可截图。
3. 生成稳定版：群像不融合。

不建议：

1. 为了爆款把治愈改成吵闹。
2. 为了可爱堆表情，忘记任务。
3. 同时测试群像、特效和长动作。

### 9.4 打斗特效

优先版本：

1. 生成稳定版：接触受力清楚。
2. 导演推荐版：主场面最有重量。
3. 传播测试版：第一帧危险感更强。

不建议：

1. 为了更炸牺牲空间方向。
2. 同时测复杂运镜和复杂动作。
3. 把爆炸当成受力结果。

### 9.5 情感品牌片

优先版本：

1. 情绪加强版：人物收回动作更真。
2. 客户安全版：品牌出现克制但清楚。
3. 发布测试版：标题偏共鸣或旧物问题。

不建议：

1. 为了品牌露出破坏余味。
2. 为了情绪过度煽情。
3. 让旁白解释所有感受。

## 10. 版本失败后的处理

| 失败症状 | 不要做 | 第一刀 |
| --- | --- | --- |
| 两版都弱 | 不要融合成更长版本 | 回到主目标，重新选主变量 |
| A版好看但不卖 | 不要只加口号 | 补产品动作或结果变化 |
| B版抓人但跑题 | 不要继续加冲突 | 回收核心信息和品牌任务 |
| 客户版安全但无聊 | 不要直接换成发布版 | 保留卖点，改第一帧和声音入口 |
| 发布版停留强但误解多 | 不要硬发 | 补信息债回报或后期澄清 |
| Seedance 版本都漂 | 不要继续 A/B 包装 | 先回到角色关键帧和生成稳定版 |

连续两轮失败：

```text
停止测试包装变量，回到主场面、第一帧、角色连续性或产品证明。版本问题可能其实是结构问题。
```

## 11. 复盘写回

每次多版本测试后，写回 6 个字段：

```text
项目类型：
测试变量：
A版表现：
B版表现：
胜出原因：
下次默认规则：
```

可以写回的位置：

1. 平台发布与爆款包装库。
2. 黄金样例基准包。
3. 错误记忆与自动避坑案例库。
4. 类型公式手册。
5. 客户反馈翻译协议。

## 12. 自检闸门

输出版本决策前检查：

1. 有没有写清主目标？
2. 每个版本有没有用途和主变量？
3. A/B 是否只改一个变量？
4. 客户版和发布版是否分流？
5. 有没有淘汰、保留或回滚判断？
6. 下一轮测试变量是否唯一？
7. 通过标准是否能检查？

## 13. 最小合格线

一次版本管理至少要输出：

1. 主目标。
2. 版本表。
3. 导演推荐。
4. 客户版或发布版去向。
5. 淘汰或回滚判断。
6. 下一轮只测变量。
7. 通过标准。

少一项，就不是版本决策，只是把选择困难写成表格。
