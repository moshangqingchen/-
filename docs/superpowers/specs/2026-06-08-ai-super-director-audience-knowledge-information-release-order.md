# AI超级导演观众知情控制与信息释放秩序协议

## 1. 定位

这份协议用于控制一条短片、短剧、广告、喜剧、情感片、悬疑片或 Seedance 多镜头项目里，观众、角色、镜头和后期文字分别在什么时候知道什么。它不替代悬疑信息差引擎；悬疑引擎专门处理秘密、伏笔和反转，本协议是跨类型的信息释放总控。

一句话原则：

```text
不是所有信息都要立刻说，也不是所有信息都要藏。
导演要决定谁先知道、谁晚知道、观众什么时候得到回报。
```

## 2. 触发信号

当用户出现以下说法时，默认调用本协议：

1. “信息怎么放、什么时候揭晓、要不要先说清”。
2. “观众会不会看不懂、会不会太早猜到”。
3. “反转太突然、铺垫不够、伏笔怎么埋”。
4. “广告卖点什么时候露出、产品什么时候出现”。
5. “喜剧误会怎么让观众先知道一点”。
6. “情感真相要不要一开始说出来”。
7. “Seedance 多镜头每镜该给多少信息”。

如果问题只发生在悬疑里，优先调用悬疑信息差、空间压迫与反转伏笔引擎。  
如果问题是整条片断电，调用观众心跳线与情绪连续性协议。  
本协议负责决定信息释放顺序。

## 3. 四个知情位置

每条片先填这张表：

| 知情位置 | 它知道什么 | 作用 |
| --- | --- | --- |
| 观众知道 | 观众已经看见或听见的信息 | 产生期待、紧张、笑点或信任 |
| 主角知道 | 主角掌握的信息 | 决定行动和防御 |
| 对手/他人知道 | 阻碍者或旁观者掌握的信息 | 制造压力、误会、反转 |
| 镜头知道 | 镜头看见但暂时不解释的信息 | 伏笔、道具、空间、声音回收 |

判断句：

```text
这一镜不是问“要不要告诉观众”，而是问“让谁比谁多知道半步”。
```

## 4. 信息释放节拍

短视频和短片里，信息要按节拍给回报：

```text
0-3 秒：给一个问题。
3-8 秒：给一点答案，但打开更大的问题。
8-20 秒：让信息改变人物行动或产品证明。
20 秒以后：回收伏笔或兑现变化。
结尾：留下余味、评论点、转化入口或追更问题。
```

长一点的项目可以按场次：

```text
第一场：观众知道问题。
第二场：角色知道代价。
第三场：对手利用信息。
第四场：镜头回收伏笔。
结尾：观众重新理解前面。
```

## 5. 类型知情策略

| 类型 | 推荐知情策略 | 不要 |
| --- | --- | --- |
| 短剧 | 观众先知道压力，主角晚一点反击 | 第一镜解释背景 |
| 喜剧 | 观众知道角色误解了，角色认真执行 | 角色自己解释笑点 |
| 创意广告 | 观众先知道痛点，产品动作再揭答案 | 一上来只喊卖点 |
| 情感短片 | 镜头先知道旧物，角色晚一点破防 | 旁白直接讲真相 |
| 悬疑反转 | 镜头先埋异常，观众得到小回报 | 所有信息都藏到最后 |
| 打斗特效 | 观众先知道空间和目标，再看接触点 | 先上满屏特效 |
| 可爱治愈 | 观众先知道小主体硬撑，温柔介入再出现 | 直接卖萌解释情绪 |
| 科普教育 | 观众先知道误解，再用演示揭答案 | 长口播堆知识 |
| B2B品牌 | 观众先知道行业压力，再看团队协作 | 先讲公司多厉害 |

## 6. 信息债与回报

每个信息债必须有回报，不要只抛问题。

```text
信息债：
观众现在想知道什么？

回报方式：
用动作、道具、产品结果、人物反应、声音或后期文字回答。

回报时间：
下一镜 / 中段 / 结尾 / 下一集。
```

常见信息债：

| 信息债 | 回报方式 |
| --- | --- |
| 为什么他不说话 | 手部防御动作或旧物回收 |
| 产品能不能解决 | 产品动作和可见变化 |
| 谁在撒谎 | 伏笔道具或反应停顿 |
| 这个规则会怎样 | 三次规则证明 |
| 为什么好笑 | 旁人反应和二次升级 |
| 为什么要继续看 | 新代价、新证据或下一集问题 |

## 7. Seedance 信息释放规则

Seedance 提示词里每镜只给一个信息变化。

```text
本镜信息目标：
观众本镜新知道：
角色本镜新知道：
镜头暂时隐藏：
下一镜要偿还：
后期文字承担：
禁止直接生成：
```

默认规则：

1. 不让一镜同时揭身份、给长对白、展示证据、完成反转。
2. 手机字、合同字、品牌字、字幕默认后期添加。
3. 信息变化必须由动作、眼神、道具、声音或结果变化承载。
4. 每镜 4-6 秒优先，只推进一个知情差。
5. 复杂反转拆成“伏笔出现、误读升级、真相露出、反应回收”。

## 8. 常见错误与第一刀

| 错误 | 表现 | 第一刀 |
| --- | --- | --- |
| 太早说破 | 观众没期待 | 延后答案，先给行为异常 |
| 藏太久 | 观众困惑 | 每 3-8 秒给一个小回报 |
| 反转突兀 | 没有前置伏笔 | 补一个画面或声音伏笔 |
| 广告卖点晚 | 观众不知道看什么 | 先给痛点，再让产品动作介入 |
| 喜剧不好笑 | 观众和角色同时不知道 | 让观众先知道角色误解 |
| 情感太直白 | 旁白说完了 | 改成旧物、手部和声音回声 |
| Seedance 信息过载 | 一镜跑乱 | 一镜只推进一个信息变化 |

## 9. 输出模板

```text
我先定信息释放：

核心信息：
【这条片最后要让观众明白什么】

知情表：
观众知道：
主角知道：
对手/他人知道：
镜头知道但不解释：

信息释放顺序：
1. 第一镜给：
2. 第二段给：
3. 中段回报：
4. 结尾回收：

最大风险：
【太早说破 / 藏太久 / 反转突兀 / 信息过载】

第一刀：
【先改哪一个信息释放点】

Seedance 字段：
本镜信息目标：
观众本镜新知道：
角色本镜新知道：
下一镜要偿还：
后期文字承担：
禁止直接生成：
```

## 10. 与其他能力衔接

默认顺序：

```text
情绪命题、观众代入与人物选择
-> 观众知情控制与信息释放秩序协议
-> 观众心跳线与情绪连续性协议
-> 镜头衔接、转场与蒙太奇语法库
-> Seedance 可生成性与拆镜决策
```

分工：

1. 情绪命题决定观众为什么在乎。
2. 本协议决定观众什么时候知道什么。
3. 观众心跳线决定观众为什么继续看。
4. 镜头衔接决定信息如何从上一镜接到下一镜。
5. Seedance 拆镜决定每镜能稳定释放多少信息。

## 11. 自检闸门

输出前检查：

1. 有没有写清观众、主角、他人和镜头分别知道什么？
2. 有没有一个核心信息？
3. 有没有信息债和回报？
4. 有没有避免太早说破和藏太久？
5. 有没有把信息落到动作、道具、声音或后期文字？
6. Seedance 每镜是否只推进一个信息变化？

## 12. 最小合格线

一次信息释放设计至少要输出：

1. 核心信息。
2. 知情表。
3. 信息释放顺序。
4. 最大风险。
5. 第一刀。
6. Seedance 信息字段。

少一项，就不是信息调度，只是剧情解释。
