# AI超级导演发布前可复述、可截图与传播记忆测试协议

## 1. 定位

这套协议用于作品发布前的最后一道传播记忆闸门。

它不承诺爆款，也不猜平台算法。它只检查一件导演能控制的事：

```text
观众看完后，能不能用一句话讲给朋友，能不能截下一帧，能不能在评论区自然接话。
```

它和相邻能力的分工：

| 能力 | 负责什么 |
| --- | --- |
| 爆款视频钩子与留存节奏引擎 | 设计前三秒问题、信息债、中段升级和完播动力 |
| 作品记忆点、视觉母题与余味系统 | 设计记忆钉子、母题回收、声音回声和余味 |
| 平台发布与爆款包装库 | 生成标题、封面、简介、置顶评论和平台适配 |
| 交付前红队审查与防翻车协议 | 从客户、观众、剪辑、生成、合规、发布六个视角挑错 |
| 本协议 | 发布前反推观众能否复述、截图、评论和转发 |

## 2. 触发信号

用户出现以下表达时，默认调用本协议：

- 发布前检查
- 爆款结构稳不稳
- 能不能火
- 会不会有人转发
- 看完记不住
- 有没有传播点
- 可复述
- 能不能讲给朋友
- 封面记忆帧
- 哪一帧最适合封面
- 标题封面稳不稳
- 评论区怎么引导
- 发布后评论区会怎么说
- 置顶评论怎么写
- 发出去前最后检查

默认开口：

```text
我先做发布前可复述测试。
不看它漂不漂亮，先看观众看完能不能讲出去、截下来、接一句话。
```

## 3. 五个测试闸门

发布前必须依次通过五个闸门：

```text
一句话复述 -> 截图记忆帧 -> 声音/动作钩子 -> 评论接话口 -> 转发理由
```

### 3.1 一句话复述

问题：

```text
观众会怎么把这条片讲给朋友？
```

合格句式：

```text
有个【人/动物/产品/角色】遇到【反常问题】，他用【一个具体动作】让【局面发生变化】。
```

不合格表现：

- 只能说“很高级、很治愈、很燃、很有电影感”。
- 复述需要解释世界观、品牌背景或太多前因后果。
- 观众只记住风格，不记得发生了什么。
- 广告只能复述口号，不能复述产品动作。

第一刀：

```text
把复述句改成一个具体动作，不改全片。
```

### 3.2 截图记忆帧

问题：

```text
哪一帧最容易被截图、做封面或被人记住？
```

合格帧必须同时具备：

1. 一个清楚主体。
2. 一个反常状态、情绪停顿、产品动作或视觉母题。
3. 不依赖字幕才能看懂。
4. 画面干净，能容纳后期标题或品牌字。
5. 缩小到手机封面仍然能看懂。

不合格表现：

- 只有漂亮空镜，没有事情发生。
- 人物太小，产品太暗，动作太碎。
- 封面靠大段文字解释。
- 画面里让 Seedance 直接生成可读中文、Logo 或品牌字。

第一刀：

```text
重选封面帧：从主动作中点、人物反应停顿、产品结果变化或结尾回收里选。
```

### 3.3 声音/动作钩子

问题：

```text
观众离开画面后，还能记住一个声音或动作吗？
```

可用钩子：

- 3 到 8 个字的短句。
- 产品启动声、开合声、落桌声、衣料摩擦声。
- 角色固定小动作。
- 变身、反杀、治愈、破防前的一拍静音。
- 一次手部动作带来的可见变化。

不合格表现：

- 只有背景音乐，没有声源。
- 只有动作堆叠，没有一个可复述动作。
- 台词太长，口型风险高，观众记不住。

第一刀：

```text
保留一个声源或动作钩子，删掉多余装饰声和空泛旁白。
```

### 3.4 评论接话口

问题：

```text
观众评论时，最自然会接哪句话？
```

合格评论入口：

- 站队：你支持谁的选择？
- 猜测：下一秒它会怎么做？
- 共鸣：你有没有遇到过这种时刻？
- 选择：你会把哪个道具/能力/产品给谁？
- 复盘：你第一次看到伏笔了吗？

不合格表现：

- “你觉得怎么样”太空。
- “喜欢就点赞”太硬。
- 评论问题和片子主动作无关。
- 广告评论只引导下单，不回答观众真实疑问。

第一刀：

```text
把评论问题绑定到主动作、角色选择、产品结果或结尾悬念上。
```

### 3.5 转发理由

问题：

```text
观众为什么会把它发给另一个人？
```

常见转发理由：

| 类型 | 转发理由 |
| --- | --- |
| 可爱治愈 | “你看这个小东西怎么努力完成大任务。” |
| 短剧反转 | “你猜他最后怎么翻盘。” |
| 创意广告 | “这个产品证明拍得很直观。” |
| 特效打斗 | “这一击的受力和反应很爽。” |
| 情感短片 | “最后那个动作有点扎心。” |
| 纪实公益 | “这件小事其实我们都忽略了。” |
| 知识科普 | “这个变化一下就看懂了。” |

不合格表现：

- 只有制作炫技，没有分享理由。
- 只有产品卖点，没有观众替别人转发的理由。
- 结尾没有余味、悬念或行动入口。

第一刀：

```text
给结尾补一个可转述的变化：反应、选择、结果、余味或下一条问题。
```

## 4. 发布后评论区反应预演

评论接话口不是只写一句“你怎么看”。发布前要先预演评论区会分成哪几种声音，再决定置顶评论和第一刀。

默认预演五类评论：

| 评论类型 | 观众会说什么 | 说明什么 | 导演动作 |
| --- | --- | --- | --- |
| 支持型评论 | “这个点我懂，我也遇到过。” | 情绪或处境被接住 | 保留主情绪，不追加解释 |
| 追问型评论 | “所以它最后为什么这样做？” | 信息债有吸引力，也可能欠清楚 | 置顶评论补半步解释，不剧透完 |
| 误解型评论 | “我以为这是在说另一个意思。” | 第一帧、标题或字幕导向歪了 | 改标题/封面/第一句后期字 |
| 吐槽型评论 | “这不就是硬广/摆拍/太假了吗？” | 产品介入、表演或场景真实感弱 | 补真实任务、反应镜或证据镜 |
| 转发型评论 | “发给某某看，这就是他。” | 有明确转发对象 | 保留可代入关系，标题别写死 |

预演时必须写至少三条“像真人会发出来的评论”，不要写抽象标签。

```text
评论区预演：
1. 支持/共鸣评论：“【一句真实评论】”
2. 追问/站队评论：“【一句真实评论】”
3. 误解/吐槽评论：“【一句真实评论】”

最危险的评论：
“【最可能带偏理解或伤害转化的一句】”

置顶评论任务：
【补理解 / 引站队 / 接共鸣 / 化解误解 / 引下一集 / 回到产品证明】

建议置顶评论：
“【一句能接住讨论、不过度解释、不硬卖的评论】”

第一刀：
【改标题、封面帧、第一句字幕、结尾余味、产品证据或评论问题中的一个】
```

### 4.1 观众三句回传门禁

发布前要把传播判断压成三句真人会说出口的话。三句都说不清，就不要继续美化包装，先改观众理解入口。

| 回传句 | 必须回答 | 不合格信号 | 第一刀 |
| --- | --- | --- | --- |
| 朋友转述句 | 观众会怎么用一句话讲给朋友，必须包含主体、反常问题或选择、可见动作或结果 | 只剩“很高级、很治愈、很燃、很好看” | 改主动作或补记忆点 |
| 评论接话句 | 观众最自然会接哪句话，必须绑住主动作、关系选择、产品结果或结尾悬念 | 只能写“你怎么看、你们觉得呢” | 重写评论问题，围绕动作、选择或结果 |
| 误解句 | 观众最可能把它看歪成什么，暴露标题、封面、第一帧、字幕或结构风险 | 误解反转了产品价值、关系方向或主题立场 | 先改标题、封面或第一帧，再考虑发布 |

硬规则：

1. 朋友转述句不能只复述氛围，必须能说出“谁做了什么，结果让人为什么想讲”。
2. 评论接话句不能只求互动，要给观众一个可站队、可共鸣、可追问或可确认的具体口子。
3. 误解句不是悲观预测，是发布前排雷；如果误解会伤害产品、人物或主题，先改入口。
4. 不承诺必爆，只判断传播入口是否够清楚。

禁忌：

1. 不要用“大家怎么看”当万能置顶评论。
2. 不要用置顶评论补救一个本该在画面里看懂的主问题。
3. 不要把所有吐槽都当坏事；能引发站队的争议可以保留，误解主旨的争议要改。
4. 广告内容不要只置顶购买引导，先回应观众最不信的产品证据。
5. 短剧内容不要把反转解释完，置顶评论只抛下一步选择或站队问题。

```text

【第几镜/哪一刻/为什么能做封面】

【一个声音、动作、短句或静音点】

评论接话口：
【观众最自然会评论什么】

评论区预演：
【三条真实评论 + 最危险的一条】

观众三句回传：
朋友转述句：【观众会怎么讲给朋友】
评论接话句：【观众最自然会怎么接话】
误解句：【观众最可能看歪成什么】

【一句】

转发理由：
【观众为什么会发给朋友】

【只选一个】

【只改一个动作、封面帧、标题问题或结尾回收】

```

## 6. 分级结论

| 结论 | 判断 | 处理 |
| --- | --- | --- |
| 可发 | 五个闸门都能被具体回答 | 进入平台发布包装 |
| 小修后发 | 主链清楚，只有一个弱项 | 只改一个传播变量 |
| 先改封面 | 复述成立，但封面帧弱 | 重选截图记忆帧 |
| 先改标题 | 内容成立，但标题复述内容或太平 | 改成问题感、冲突感或选择感 |
| 先补记忆点 | 看完说得清但记不住 | 接作品记忆点系统补母题、声音或动作 |
| 先改主结构 | 观众无法复述发生了什么 | 接导演改稿手术，不急着发 |

## 7. 类型化第一刀

| 类型 | 最常见弱项 | 第一刀 |
| --- | --- | --- |
| 可爱治愈 | 太软，没有任务 | 给小主体一个大任务和一个反应停顿 |
| 短剧 | 复述像剧情简介 | 改成身份问题、阻碍者和选择代价 |
| 创意广告 | 只记得口号 | 补产品动作、结果变化和人物确认 |
| 特效打斗 | 只记得炸 | 补接触点、受力结果和反应镜头 |
| 情感短片 | 情绪太满 | 把大哭改成一个收回动作 |
| 企业品牌 | 只记得公司很厉害 | 改成团队完成一个具体任务 |
| 文旅城市 | 只记得风景漂亮 | 补路线、人的停顿和地方声音 |
| 科普教育 | 信息讲完但没记住 | 补一个可见实验变化和一句记忆结论 |

## 8. 与 Seedance 2.0 的衔接

发布前如果发现截图帧或记忆动作弱，不要整条重写，先生成最小测试小样：

```text
只测一个变量：
截图帧 / 主动作 / 产品结果 / 角色反应 / 声音钩子 / 结尾回收

不测：
完整剧情、所有台词、复杂转场、多人物群像、长字幕、Logo生成

通过标准：
手机缩略图能看懂主体；
观众能一句话说出发生了什么；
画面留出后期标题和字幕安全区；
动作或声音能被复述。
```

Seedance 提示词里只写画面和动作，标题、Logo、品牌字、可读中文和长字幕后期添加。

## 9. 回归测试

输入：

```text
这条片准备发了，帮我看看爆款结构稳不稳，观众会不会记住。
```

合格输出必须包含：

1. 观众一句话复述。
2. 最强截图帧。
3. 声音或动作钩子。
4. 评论接话口。
5. 评论区预演和建议置顶评论。
6. 观众三句回传：朋友转述句、评论接话句、误解句。
7. 转发理由。
8. 最弱项和第一刀。
9. 不承诺必爆，不用“会火”当结论。
